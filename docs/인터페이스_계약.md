## 2. 데이터 형식 (원본과 같다. 바꾸지 않는다)
- **채보 v2(편집용)**: `schema_version: 2`, `song`, `timing`(tick 기반, 1박=960tick, `bpm_map`, `grid_map`), `sections`, `lanes: 2`, `difficulties[{name, level, notes[]}]`, `meta`. 노트 3종 `tap`/`hold`(`length_tick`)/`burst`(`length_tick`, `count`, lane은 `"both"`). 정의 원본: `D:\MusicNoteDesignProgram\app\core\schema.py`, `prompt\02_데이터포맷_노트3종.md`.
- **Unity용 내보내기**: 노트가 `{type, lane, time_ms, duration_ms, count}`로 ms 정수 변환된 목록(`audio_offset_ms`·`decoder_delay_ms` 합산 완료). **플레이 화면은 이 형식(또는 이것을 `src\chart\chartLoader`가 읽는 형태)만 입력으로 받는다.**
- **분석 결과(AnalysisResult)**: (01a 확정 2026-11-05) 원본 `analysis.json`(`analyze.py`의 `run`)과 **같은 필드 이름·단위**이고 `waveform`만 더했다. 시간은 모두 **ms(밀리초), 음원 0ms 기준**. 정의: `src\analysis\types.ts`.
  | 계약 초안의 이름 | 실제 필드(JSON 경로) | 단위·설명 |
  |---|---|---|
  | `bpm` | `timing.bpm` | BPM. `timing.source`가 `auto`(자동)·`manual`(직접 입력). 자동 값은 `timing.auto.bpm`, 박 추적 직후 값은 `timing.auto.before.bpm` |
  | `offset_ms` | `timing.audio_offset_ms` | "tick 0이 음원의 몇 ms 지점인가". 자동 값은 보통 0 이하(첫 박 한 칸 앞) |
  | `beats_ms[]` | `beats.beats_ms` | 찾은 박의 위치(ms, 0.1 단위). `beats.beat_count`는 개수 |
  | `candidates[]` | `candidates` | `{time_ms(소수 2자리), strength(0~1, 소수 4자리), band('low'\|'mid'\|'high'), duration_ms(소리가 이어지는 길이, 소수 1자리)}`. `candidate_count`는 개수 |
  | `duration_ms` | `info.duration_ms` | 곡 길이. `info`에는 `sample_rate`(22050), `lead_silence_ms`(앞 무음)도 있다 |
  | `waveform` | `waveform` | `{step_ms:10, duration_ms, min:number[], max:number[]}` (10ms마다 최소·최대 진폭, 원본 `waveform.json`과 같은 모양) |
  | `bpm_candidates[]` | `beats.bpm_candidates` | `{bpm, kind('주 후보'\|'반 박'\|'두 배 박'\|'3/2 박'\|'2/3 박'), confidence(0~1)}`. 뒤 2개는 01a의 호환 추가 |
  | `grid_fit` | `grid_fit` | `{total, fit, percent, division(8), tolerance_ms(30)}` — 소리 시작 지점이 8분 격자에서 ±30ms 안에 든 비율 |
  | (그 밖) | `version`, `song`(곡 이름, 저장소가 채움), `audio_sha256`(저장소가 채움), `created_at`, `options{detector, sensitivity, min_gap_ms}`, `beats{interval_cv, has_downbeats, librosa_bpm}`, `warnings[]`(쉬운 한국어), `timing.user`(직접 입력 값 또는 null) |
  예시(축약): `{"version":"0.1.0","timing":{"source":"auto","bpm":125.569,"audio_offset_ms":-294.59,"auto":{...},"user":null},"beats":{"bpm_candidates":[{"bpm":125.57,"kind":"주 후보","confidence":1}],"beats_ms":[121.5,...]},"candidates":[{"time_ms":412.6,"strength":0.8123,"band":"low","duration_ms":143.5}],"grid_fit":{"total":830,"fit":425,"percent":51.2,"division":8,"tolerance_ms":30},"info":{"sample_rate":22050,"duration_ms":235357.46,"lead_silence_ms":0}, "waveform":{"step_ms":10,...}}`
- **생성 옵션(GenerateOptions)**: (01a 확정 2026-11-05) 원본 `generate.generate(analysis, options)`가 받는 필드 전부, 이름도 같다(`snake_case`). 모두 선택이며 빠진 값은 난이도 프리셋(`config\presets.json`)·기본값이 채운다. 정의: `src\generate\types.ts`.
  `ratios{tap,hold,burst}`(합 100, 기본 70/20/10) · `hold_beats`(0.25~16, 기본 1.0) · `burst_count`(3~100, 기본 8) · `difficulty`(`EASY|NORMAL|HARD|CUSTOM`, 기본 NORMAL) · `lane_mode`(`alternate|pair|accent|random`, 기본 alternate) · `design_mode`(`classic|reference|unified`, 기본 classic) · `grid_tolerance`(`strict|normal|loose`, 기본 strict=30ms) · `grid_division`(4·8·12·16·24·32, 난이도 기본값 덮어쓰기) · `nps_base`·`max_nps`(초당 노트 수) · `min_gap_ms` · 통합 규칙 전용: `range_start_ms`·`range_end_ms`(노트 구간, 기본 곡 전체)·`target_nps`(0.3~8)·`allow_burst`(bool). 시드는 옵션이 아니라 `config\presets.json`의 `generation.seed`(19491)이며 같은 시드·같은 입력이면 같은 채보다(원본 파이썬 `random`과 같은 난수열).
  **생성 결과(GenerateResult)** = `{notes, difficulty, timing{bpm_map,grid_map,audio_offset_ms,source}, stats{total,tap,hold,burst,*_percent,requested_percent,nps{avg,max,p90},process,design_mode,rule_problems}, validation, messages[], options_used, chart}` — `chart`는 채보 v2(난이도 1개).
- **검증 결과**: (01a 확정 2026-11-05) 원본 `/validate` 응답과 같다. `validateChart(chart)` → `{errors:number, warnings:number, issues:Issue[]}`, `Issue = {level:'error'|'warning', code, message(쉬운 한국어, "[난이도] ..." 형식), difficulty, note_ids:number[](편집기가 노트로 이동할 때 사용)}`. 오류 코드: `lanes, timing, dup_id, bad_type, bad_lane, bad_tick, bad_length, bad_count, duplicate, over_duration, burst_overlap, overlap_same_lane`(+`opposite_lane`은 정책이 error일 때). 경고 코드: `decoder_delay, before_start, opposite_lane, burst_too_fast, hold_too_short, same_lane_run, too_dense, too_many_simultaneous`. 기준 숫자는 `config\validate.json`. 생성 결과 안의 `validation`은 요약형 `{error_count, warning_count, items:Issue[](최대 30개)}`.

**2026-11-05 (01a)** — 3절 함수 모양을 TypeScript로 구현하면서 생긴 **추가(기존 모양은 그대로)**
- 가져오기 위치: `src\core\index.ts`(core 전체), `src\analysis\index.ts`(분석), `src\generate\index.ts`(생성). 파일 확장자 `.ts`를 붙여 가져온다(`from '../core/index.ts'`).
- `validateChart(chart, opts?)`는 `{errors, warnings, issues}` 를 돌려준다. 이슈 목록만 필요하면 `validateIssues(chart, config?)`(원본 `validate_chart`와 같은 반환).
- `retime(chart, change)`는 새 `ChartV2`만 돌려준다. 안내 메시지(앞당김·재계산 뒤 새 오류)가 필요하면 `retimeChart(chart, bpmEntries, offsetMs, mode)` → `{chart, messages}`. `RetimeChange = {bpm_map?, audio_offset_ms?, mode?: 'time'|'tick'}`.
- `judge(type, noteMs, lengthMs, pressMs, releaseMs, cfg?)`는 단타·롱노트용. 연타는 `judgeBurst(startMs, lengthMs, pressTimes, count)`. 단타·롱노트 개별 함수 `judgeTap`, `judgeHold`도 공개. 판정 등급 폭은 `config\judge.json`(`loadJudgeConfig()`).
- `exportUnity(chart, difficulty?)` → `UnityChart`(원본 `build_unity_data`와 같은 모양: `format:'two-key-unity.v2'`, `song`, `lanes`, `lane_values`, `judge`, `note_rules`, `difficulties[{name, level, notes[{type, lane, time_ms, duration_ms, count}]}]`). 오류가 있으면 `ExportBlocked`(`.issues`)를 던진다. 난이도별 파일 분리용 `exportUnitySplit(chart)`, 편집용 JSON 문자열 `exportEditJson(chart)`.
- 저장·불러오기(문자열): `chartToJson(chart)`, `chartFromJson(text)`, `loadChartData(obj)` → `{chart, issues, converted_from, conversion_notes}`; v1 변환 `convertV1ToV2`; 샘플 `buildSampleChart()`; 해시 `sha256Hex(bytes)`; 이름 정리 `safeName`.
- `decodeToMono22k`는 계약의 `{samples, sampleRate, durationMs}`에 `leadSilenceMs`, `originalPeak`을 더해 돌려준다. 소리는 최대 진폭 0.99로 맞춘다. **화면(메인 스레드)에서만** 쓴다(워커 안에서는 `OfflineAudioContext`가 없다).
- `buildWaveform(samples, buckets)`는 길이 `buckets*2`의 `Float32Array`이고 `[최소0, 최대0, 최소1, 최대1, …]` 순서다. 원본 모양의 요약은 `waveformSummary(samples, 22050, 10)`이며 `analyzeAudio` 결과의 `waveform`에 들어 있다.
- `analyzeAudio(samples, opts, onProgress?, signal?)`: 4번째 선택 인자 `AbortSignal`을 더했다. `AnalyzeOptions`는 `{detector, sensitivity, minGapMs, manual?: {bpm, audio_offset_ms?}}`. `detector`는 01a에서 `hybrid|flux|bass|treble|energy`만 동작하고 `drums|melody|vocal`은 "준비 중" 오류(01b에서 채움). 진행률 단계 이름: "소리 불러오는 중"(파일 읽기) → "소리 준비하는 중" → "소리의 변화를 분석하는 중" → "소리 시작 지점을 고르는 중" → "박자 찾는 중" → "노트 후보를 정리하는 중" → "분석이 끝났습니다.".
- **화면이 쓰는 분석 호출은 `src\analysis\workerClient.ts`의 `analyzeInWorker(fileOrBufferOrSamples, opts, onProgress)` 한 곳**이다. `cancelAnalysis()`로 취소(분석 Promise는 `AnalysisAborted`로 거부), 새 분석이 오면 앞의 것은 자동 취소. 분석 오류는 `AnalysisError`(메시지가 쉬운 한국어).
- `generateChart(analysis, options)`는 계약의 `{chart, stats, validation}` 외에 `notes, difficulty, timing, messages, options_used`도 돌려준다(원본 `generate()` 반환값 전체). 곡 이름은 `analysis.song`에서 `chart.song.title`로 들어간다(분석 결과의 `song`을 저장소가 채워 두면 된다).
- **분석 모드 등록소(01b용)**: `src\analysis\modeRegistry.ts`의 `registerMode(id, fn)`. 01b는 `src\analysis\modes\`(01a가 빈 `index.ts`를 만들어 둠) 안에서 `drums|melody|vocal`을 등록하면 되고, `analyze.ts`는 건드리지 않는다. `fn({samples, features, options, report, signal})`은 `Candidate[]` 또는 `{candidates, warnings?}`를 돌려준다. 등록되지 않은 방식은 "준비 중" 오류.
- 설정 읽기: `src\core\config.ts`의 `loadJudgeConfig/loadValidateConfig/loadAppConfig/loadPresets`. `config\app.json`에는 서버 전용 항목(`idle_exit_sec` 등)을 뺐고 `analysis_sample_rate`, `analysis_max_minutes`만 있다.
- 임시 스텁: `src\app\main.ts`와 `index.html`의 스크립트 연결은 01a가 빌드 확인용으로 만든 **스텁**이다. 02단계가 `main.ts`를 실제 화면 코드로 교체한다.

**2026-11-05 (01b)** — 분석 모드 추가에 따른 **호환 추가**(기존 모양은 그대로)
- `AnalysisResult`에 선택 필드 `mode`(쓴 분석 방식 이름: `hybrid|bass|drums|melody|vocal` 등, `options.detector`와 같은 값)를 더한다. 붙이는 곳은 `src\analysis\modes\analyzeWithMode.ts`의 `analyzeAudioWithMode`·`analyzeFileWithMode`(둘 다 `modes\api.ts`로 공개)이다. 없는 결과(옛 저장분·워커를 직접 부른 경우)는 `options.detector`를 쓰면 된다.
