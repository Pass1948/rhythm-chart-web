# 리듬 채보 만들기 (웹) 최종 보고

작성일 2026-11-06 (06 최종 점검 반영: 파형·변속 구간·탭 소리 파일·새 배치 포함). 이 문서는 "무엇이 만들어졌고, 어떻게 쓰고, 어디까지 믿을 수 있고, 어떻게 올리는지"를 한곳에 모은 것입니다. 단계별 자세한 기록은 `prompt\result\`의 결과 md들에 있습니다.

## 1. 한눈에 보기

주소만 열면 누구나 쓰는 웹 프로그램입니다. 서버가 없고, **음원 파일은 내 브라우저 밖으로 나가지 않습니다.** (파일은 이 브라우저의 저장 공간에만 보관됩니다.)

사용 흐름은 다섯 단계입니다.

1. **곡 올리기**: 음원 파일을 올리거나, 처음이면 [체험용 데모 곡]으로 시작합니다. (데모 곡은 코드로 만든 소리라 음원 파일이 들어 있지 않습니다.)
2. **분석**: 분석 방식(종합·베이스·드럼·멜로디·보컬)을 고르고 [분석]을 누릅니다. 박자(BPM)와 "소리가 시작되는 지점"(노트 후보)을 찾습니다. 진행률이 보이고 화면은 멈추지 않습니다.
3. **노트 생성**: 난이도(EASY·NORMAL·HARD)와 디자인 방식을 고르면 후보에서 채보(노트 배치)를 자동으로 만들어 줍니다. 오류·경고 검사가 함께 돌아갑니다.
4. **편집**: 세로 편집기에서 단타·롱노트·연타를 놓고 지우고 옮깁니다. 되돌리기, 복사·붙여넣기, 박자 보정, 메트로놈이 있습니다.
5. **게임 화면 테스트**: [게임 화면 테스트]를 누르면 만든 채보를 실제 리듬게임 화면에서 쳐 봅니다. 결과 화면에서 놓친(MISS) 노트를 누르면 편집기의 그 노트로 돌아가 고칠 수 있습니다.

저장·내보내기: 작업은 자동으로 이 브라우저에 저장됩니다. [내보내기]로 채보 파일(편집용 JSON, 게임용 Unity JSON)을 내려받을 수 있습니다.

## 2. 분석 모드 5개와 한계

**왜 "근사"인가요?** 악기를 정말로 따로 떼어 내려면 인공지능 모델(예: demucs)이 필요하고 파일이 수백 MB입니다. 이 프로그램은 서버가 없고 올리는 파일 크기에 제한이 있어서 **모델을 쓰지 않습니다.** 대신 소리의 주파수·세기 변화로 "드럼 같은 소리", "멜로디 같은 소리", "가운데서 들리는 보컬 같은 소리"를 **추정**합니다. 그래서 드럼·멜로디·보컬 모드는 화면에 "근사 결과"라고 안내가 붙고, 곡에 따라 맞는 정도가 크게 다릅니다.

| 모드 | 하는 일 | 믿을 만한 정도 |
|---|---|---|
| 종합 (기본) | 전체 소리의 변화에서 시작 지점을 찾음 | 원본 프로그램과 **같은 후보**가 나오도록 검증함. 6곡에서 F1(후보가 얼마나 일치하는지, 1이 완전 일치) 1.000 |
| 베이스 | 저음 변화만 봄 | 종합과 같은 계열의 검출기라 안정적. 저음이 약한 곡은 후보가 적음 |
| 드럼 (근사) | 소리를 "툭 치는 소리(타악)"와 "이어지는 소리(화음)"로 나눈 뒤 타악 쪽에서 찾음 | 합성 드럼 테스트에서는 잘 맞음. 실제 곡에서는 베이스·보컬 일부가 섞여 들어옴 |
| 멜로디 (근사) | 같은 방식으로 화음 쪽에서 음이 바뀌는 지점을 찾음 | 음 바뀜은 잘 찾으나 악기 구분은 못 함 |
| 보컬 (근사) | 좌우 소리가 같은 "가운데 성분"을 뽑아 그 변화를 봄 | 스테레오 곡에서 보컬 위치를 대략 따라감. 모노 곡은 정확도가 낮다고 안내함 |

측정 수치 (01a·01b 기록에서 인용, 원본 분석 캐시 6곡):

| 항목 | 결과 |
|---|---|
| 종합 모드 후보 일치 (원본 대비) | 6곡 모두 후보 개수·위치가 같음 (F1 1.000) |
| 박자(BPM) 일치 | 6곡 중 5곡 일치. 1곡(셋잇단 느낌이 강한 곡)은 3/2배로 잡히며, 정답은 BPM 후보 목록의 "2/3 박" 항목에 있어 화면에서 고를 수 있음 |
| 채보 생성 이식 정확도 | 원본과 같은 입력이면 54개 조합 모두 노트 목록이 완전히 같음 |
| 분석 시간 (약 4분 곡, 개발 PC) | 종합 2~4초, 드럼·멜로디 약 7~10초, 보컬 약 5~7초 |
| 보컬 근사 vs demucs 보컬 시작 지점 | 포착 약 81%, 적중 약 32~33% (우연으로 맞출 때의 기준: 포착 51~56%, 적중 20%). 곡에 따라 적중 8~9%까지 낮음 |
| 드럼↔멜로디 후보가 서로 다른가 | 1대1로 짝지은 겹침 34~48%, 합성 음원에서는 뚜렷하게 갈림. 단 방향별 겹침은 80%를 넘는 곡이 있음(후보가 촘촘해서 우연히도 겹침) |

쉬운 말로: **종합은 믿고 쓰셔도 되고, 드럼·멜로디·보컬은 "초안을 빨리 뽑는 도구"로 보세요.** 결과가 마음에 들지 않으면 민감도·최소 간격을 조절하거나 편집기에서 고치세요. 템포가 변하는 곡은 BPM 하나만 만듭니다.

**편집기 화면 배치 원칙(07, 사용자 결정)**: 위 "화면 구성" 표의 배치가 기준입니다. 이 배치를 바꾸려면 사용자 승인이 필요합니다(`00_공통규칙.md` 6절). 왼쪽 열 폭은 분석 카드 글자가 잘리지 않도록 320px 이상(넓은 화면 최대 400px)으로 둡니다.

**게임 플레이 옵션** (게임 화면 테스트에만 적용되고, 편집기 [테스트]·채보 파일·내보내기는 바뀌지 않습니다):
- **볼륨**: 음악 볼륨·효과음 볼륨(0~100)과 [음소거]가 시작 전 창·일시정지 시트·PC 옆 패널에 있습니다. 플레이 도중에도 바로 적용되고, 음소거를 풀면 이전 값으로 돌아갑니다. 음악 볼륨은 편집기 음원 카드의 볼륨과 같은 값이며, 소리 크기는 슬라이더 값의 제곱 곡선입니다.
- **판정 설정**: [판정 설정]을 펼쳐 ① 판정 폭(PERFECT 10~80 / GREAT 40~140 / GOOD 70~200 / BAD 100~260ms, 항상 PERFECT<GREAT<GOOD<BAD이고 단계 사이 5ms 이상) ② 점수 비율(PERFECT 100%·MISS 0% 고정, GREAT·GOOD·BAD 0~100% 이고 큰 등급 이상) 를 바꿉니다. 판정 설정 안에는 "연타 성공은 GREAT로 계산됩니다." 안내가 있습니다(연타는 원본 규칙대로 GREAT 고정이며 설정으로 바꿀 수 없습니다). 프리셋: 원본 기본(45/95/150/200ms) · 엄격(30/65/100/140ms) · 넉넉하게(60/120/180/240ms) · 직접. 엄격·넉넉하게 값은 임시이며 `src\play\playOptions.ts` 한 곳만 고치면 됩니다. **플레이 도중에는 바꿀 수 없고**, 시작 전 또는 일시정지 중에 바꾸면 **다음 시작(처음부터 다시 포함)부터** 적용됩니다. 기본값이 아니면 결과 화면 맨 위에 "판정 설정: 엄격 (PERFECT ±30ms …)"이 작게 보입니다.

게임 시작 준비 화면에서 재생 속도(0.5~1.25배)와 시작 위치(처음부터 / 편집기 위치부터)를 고르고, 연습 모드(실패 없음)를 켜고 끌 수 있습니다.

## 4. 알려진 한계·보류 항목

- **분석 모드 한계**: 위 2절. 특히 드럼·멜로디·보컬은 근사입니다.
- **변속 자동 찾기는 합성 데이터로만 검증됨**: 박 위치를 가짜로 만들어 넣은 시험(변속 2곳·흔들림·옥타브 오류·연속 가속)만 통과했습니다. 분석의 박 추적이 고정 BPM 하나로 박을 따라가므로 **실제 곡의 변속에서는 정확도가 떨어질 수 있고, 실제 곡 결과는 사용자가 직접 확인**해야 합니다. 맞지 않으면 [변속 구간] 카드에서 구간을 손으로 고치세요(수동 편집은 정확히 동작).
- **분석 모드는 근사 방식**: 인공지능으로 악기를 분리하지 않으므로 드럼·멜로디·보컬 후보는 초안 수준입니다(2절).
- **화면·소리·조작감은 사람이 확인**: 자동 점검은 배치·글자 잘림·콘솔 오류·계산 결과만 봅니다. 실제 모양, 소리(판정음·메트로놈), 터치감, 재생 줄 위치 막대 조작감은 직접 써 보고 확인해야 합니다.
- **민감도만 바꿔도 다시 분석**: 원본처럼 후보만 즉시 다시 고르지 못하고 매번 전체를 분석합니다(데모 곡 1~2초, 4분 곡 약 4~10초).
- **연타가 있으면 만점이 안 나옴**: 연타는 원본 규칙대로 GREAT(0.7배)로 계산됩니다. 그래서 연타가 있는 채보는 올 퍼펙트여도 만점이 안 나옵니다. 점수는 조건에 따라 다릅니다: **실제 게임처럼 피버 보너스(×1.5)가 적용되는 조건에서는 약 92.6만점**, 회귀 테스트(`test\playOptions.test.ts`)처럼 **피버 배율을 1로 둔 조건(연타 1개·단타 4개)에서는 94만점**입니다. 둘은 조건이 달라서 생긴 값이고 판정 규칙은 같습니다. 연타 성공 등급은 설정으로 바꿀 수 없고, 점수 비율에서 GREAT 값을 바꾸면 연타 점수도 그 값을 따릅니다.
- **블루투스 싱크(08)**: 화면(노트 위치)과 판정이 모두 "귀에 들리는 곡 시간"(getOutputTimestamp 기준, 부드럽게 다듬음) 하나를 씁니다. 그래도 블루투스는 기기가 보고하는 지연이 실제보다 작은 경우가 많아, 시작 준비 화면의 **[싱크 맞추기]**(60BPM 박자 소리 16번, 처음 4번 제외 중앙값)로 이 기기의 입력 보정(−500~+500ms)을 맞춥니다. 값은 이 기기 설정에 저장되며, 스피커를 바꾸면(블루투스 ↔ 폰 스피커) 다시 맞춰야 할 수 있습니다. 판정 상세("빠름/느림 표시")를 켜면 화면 구석에 "기기 소리 지연 약 N ms · 최근 판정 평균 ±N ms"가 보입니다. 박자 소리 간격이 1000ms라 한 박 안(±500ms)에서 어긋나는 경우까지 자동으로 계산하고, 그보다 크게 어긋나면 숫자 칸에 직접 입력하세요.
- **음원 카드 노트 줄 편집(09, PC만)**: 음원 카드(가로 타임라인)의 왼쪽·오른쪽 노트 줄에서도 오른쪽 채보 편집과 같은 방식으로 노트를 추가·선택·이동·길이 조절·삭제할 수 있습니다(도구 버튼 `선택/단타/롱노트/연타`는 오른쪽과 같은 도구를 같이 씀, 눈금자·파형·소리 시작 지점을 누르면 재생 위치 이동, 폭 1024px 미만은 보기 전용). 눈과 빠른 입력용이며 세밀한 편집은 오른쪽 채보 편집에서 하세요. 편집 격자는 지금의 박자 기준 그대로입니다.
- **게임 화면 롱노트 모양(09)**: 롱노트가 단타와 같은 크기의 머리를 가진 둥근 긴 막대(캡슐)로 그려집니다. 연타는 줄무늬 막대 그대로입니다.
- **채보 편집 폭 조절(08)**: PC(폭 1024px 이상)에서 가운데 열과 오른쪽 채보 편집 사이 손잡이를 끌면 편집 폭이 바뀝니다(최소 380px, 최대 화면의 65%와 가운데 열 420px 남기기 중 작은 값). 더블클릭하면 기본 폭이고, 정한 폭은 이 기기에 저장됩니다. 폰·태블릿 탭 화면에는 없습니다.
- **입력 지연·낙하 시간·판정 설정은 실시간 적용 안 됨**: PC 옆 패널의 입력 지연·낙하 시간 슬라이더는 다음 시작부터 적용됩니다(지금 바로 바꾸려면 일시정지 화면). 판정 설정도 공정한 판정을 위해 다음 시작부터 적용됩니다. 볼륨만 도중에 바로 바뀝니다.
- **파일 저장 방식(04d)**: 저장 창을 띄울 수 있는 브라우저(PC 크롬 계열)는 "다른 이름으로 저장" 창, 그 밖은 다운로드 폴더로 저장합니다. 음원은 ZIP에 담아 내보냅니다(채보는 json, 여러 개·음원은 zip).
- **ZIP 읽기**: 이 프로그램이 만든 ZIP(압축 없음)과 일반 ZIP(deflate)을 읽습니다. 브라우저에 압축 해제 기능이 없으면 압축 없는 ZIP만 읽고 안내합니다. 암호·4GB 초과 ZIP은 열 수 없습니다.
- **변속 곡**: 게임 화면 테스트의 롱노트 틱 간격은 곡 첫 구간의 BPM을 씁니다(점수 틱 계산용이며 노트 시각은 구간별로 정확합니다).
- **파형 용량**: 곡마다 파형 약 48KB(4분 기준)가 곡 데이터와 따로 저장됩니다. 예전에 저장한 곡(04d의 주파수 표만 있는 곡 포함)은 열 때 한 번 계산해 채우며(수 초) 그동안 띠에 "계산 중…"이 보입니다.
- **iPad 가로(폭 1024 이상)**: PC 배치(맨 위 곡 등록 줄 + 3열)로 보이며 터치 영역은 PC 크기입니다(손가락으로 쓰기엔 작을 수 있음).
- **[테스트] 팝업**: 새 창을 여는 방식이라 게시 환경이 팝업을 막으면 "팝업이 막혔습니다"가 뜹니다. 대신 [게임 화면 테스트]를 쓰면 됩니다.
- **Worker를 못 쓰는 환경**: 분석을 화면에서 직접 돌립니다. 느릴 수 있고 "속도가 느릴 수 있습니다"라고 안내합니다. 드럼·멜로디 모드의 소리 나누기 단계(HPSS)는 한 덩어리로 계산되어 그 순간에는 화면이 잠깐(곡 길이에 따라 수 초까지) 멈출 수 있습니다.
- **저장소가 막힌 환경**(시크릿 모드 등): "저장되지 않습니다. 작업 후 [내보내기]로 저장하세요"라고 안내하고 메모리 모드로 계속 동작합니다. 새로고침하면 사라집니다.
- **브라우저 범위**: 크롬(헤드리스)과 터치 에뮬레이션으로만 확인했습니다. 사파리·파이어폭스·실제 폰은 미확인입니다.
- **점검용 도구 유지**: `window.__rcwPlay`, `__rcwLayout`, `__editor`는 읽기 전용 점검 도구로 배포에도 남겨 둡니다(옆 패널 숫자가 `__rcwPlay`를 읽음).
- 토스트(알림 상자) 긴 글이 편집기 일부를 잠깐 가릴 수 있습니다.

## 5. 실제 기기에서만 확인할 것

- **폰 터치감**: 길게 누르기 시간(420ms)·이동 허용(10px)이 손에 맞는지, 노트 이동·끝 늘리기가 편한지, 두 손가락 핀치.
- **iPhone(사파리) 소리**: 단타 판정음은 사용자가 준 `TapSound.wav`(빌드에 포함, 읽기 실패 시 합성음)이고 나머지 효과음은 코드로 합성합니다. 처음 터치 뒤에 오디오를 켭니다. iPhone에서 소리가 나는지, 무음 스위치의 영향, 재생 시작 지연을 확인하세요.
- **성능**: 중저가 폰에서 4분 곡 분석 시간(특히 드럼·멜로디·보컬), 게임 화면(Three.js) 프레임, 발열.
- **소리 품질**: 헤드리스 점검에서는 실제 소리를 귀로 확인하지 못했습니다. 판정음·효과음을 한 번 들어 보세요.
- **저장 동작(04d)**: PC에서 [저장]을 눌렀을 때 저장 위치를 고르는 창이 뜨는지, 폰(특히 iOS 앱 공유 시트·안드로이드 다운로드 폴더)에서 ZIP이 실제로 저장되는지, 저장한 `채보+음원` ZIP을 다시 [불러오기]로 열면 같은 곡이 복원되는지 확인하세요. 
- **게시 환경에서의 동작**: GitHub Pages 주소에서 저장소(IndexedDB)·Worker·팝업이 동작하는지. 막혀도 계속 동작하도록 만들어 두었지만 실제 안내 문구가 맞게 뜨는지 확인하세요.

## 4키 모드 (10단계)
- 노트 생성 카드의 **키 모드** 상자에서 2키(기본)/4키를 고른다. 노트가 하나도 없는 채보는 고르는 즉시 바뀌고, 노트가 있는 채보는 [노트 자동 생성]으로 다시 만들 때(기존 교체 확인) 바뀐다.
- 4키 채보는 오른쪽 편집과 음원 카드 모두 레인 4줄(1~4레인 = 게임에서 S D K L). 같은 위치에는 노트 최대 2개, 롱노트 유지까지 포함해 동시에 눌러야 하는 노트는 2개까지(13단계, 양손 엄지 기준). 같은 손(S·D 또는 K·L) 두 레인 동시는 검사에서 경고. 레인 교체·좌우 뒤집기는 1↔4, 2↔3.
- 게임 화면: 판정 원 4개(레일을 4등분), 키는 S D K L 고정(설정에서 못 바꿈), 폰은 화면을 4구역으로 나눠 가장 가까운 레인에 입력. [싱크 맞추기]는 아무 키·터치.
- [테스트] 팝업은 자체 2D 그림으로 4레인을 그리고 S D K L·4등분 터치로 친다(롱노트 캡슐 모양은 바뀌지 않음).
- 2키 채보·JSON은 그대로 열린다. 4키 JSON을 옛 앱이 열면 "레인 수는 2개만 지원" 오류로 막힌다.


## 새 게임 화면 10-C (11단계)
- 게임 시작 준비 화면의 [화면 모양]에서 [기존 화면] / [새 화면 10-C]를 고른다(선택은 저장되고 기본은 기존 화면). 10-C의 노트 속도는 기존 화면과 따로 저장되며 기본 1.4초, 일시정지 창의 낙하 시간으로 바꿀 수 있다.
- 10-C는 720×1280 Canvas 2D로 레일(2·4레인)·몬스터·체력바(곡 전체 노트 수에 맞춰 곡 끝에 0)·주인공·타격 이펙트·진행 막대·곡명 칸(업로드한 파일 이름)·SCORE·콤보·좌우 게이지·판정 글자를 직접 그린다. 점수·판정·콤보·피버·부정수치는 기존 규칙이 계산한 값을 그대로 보여 준다.
- 연타는 레일 전체 폭의 줄무늬 막대(어두운 바탕 + 크림색 사선 줄무늬 + 밝은 테두리, 가운데 "×남은 횟수")로 그린다.
- PC에서는 세로 화면 양옆을 불투명한 어두운 색으로 덮는다. 터치는 10-C 판정원 사이를 경계로 한 구역(4레인 3개 경계)이다. [테스트] 팝업은 바뀌지 않았다.
- 알려진 한계: 캐릭터 잔상은 끔 값이라 구현하지 않았고, 효과음은 기존 TapSound.wav 경로 그대로다(음량 60·꼬리 정리 300ms 값은 설정 파일에만 기록).


## 4키 전용 생성 (13단계, 모바일 양손 엄지 기준)
- 왼손 = 레인 1·2(S D), 오른손 = 레인 3·4(K L). 4키를 고르면 타이밍 후보·노트 종류·길이 계획은 그대로 쓰되 목표 밀도에 **4키 노트 양 배율**(쉬움 ×1.15, 보통 ×1.25, 어려움 ×1.3)을 곱하고, 레인은 손 기준으로 새로 정한다(2키 결과는 그대로).
- 손 규칙: 동시 입력은 롱노트 유지 포함 최대 2개·양손에 하나씩, 롱노트를 누르는 손은 끝날 때까지 쉬고, 빠른 연속(220ms 미만)은 손 교대, 같은 손 연속은 150ms 이상, 좌·우 손 비율은 50:50 근처.
- 1~2마디마다 패턴(계단·양손 트릴·손 교대·점프)을 고정 시드로 골라 쓴다. 동시 노트는 **동시 노트 비율**(쉬움 0%, 보통 5%, 어려움 10%)만큼 마디 첫 박·박·세기가 강한 곳에 다른 손 단타를 더한다.
- 노트 생성 카드에서 4키일 때만 [4키 노트 양 배율](1.0~1.6)과 [동시 노트 비율 %](0~30)가 보인다. 기본값은 `config\presets.json`의 `four_key`, 바꾼 값은 난이도별로 이 기기에 저장된다.
- Unity 4키 규칙(형식 `four-key-unity.v2`): 같은 `time_ms` 시작은 최대 2개, **롱노트 유지까지 포함해 동시에 눌러야 하는 노트는 2개 이하**, 롱노트 진행 레인에는 다른 노트 없음, 연타 구간 안에는 다른 노트 없음. 같은 손 두 레인 동시는 권장하지 않음(편집기 검사 경고).


## 디자인 모드 조절 칸 (14단계)
- 세 모드(기존·레퍼런스·통합)의 차이는 "지키는 규칙"뿐이고, 조절 칸(노트 양, 노트 종류 비율, 롱노트 기본 길이, 연타 기본 횟수)은 모두 열려 있다. 레퍼런스·통합은 그 모드·난이도의 규칙 기본값이 미리 채워지고(옆에 "규칙 기본값"), 바꾼 값이 규칙보다 우선한다.
- [고급 규칙](접기 칸): 레퍼런스 6개(레인 전환 확률·같은 레인 최대 연속·지그재그 한도·롱노트 중 노트 수·연타 뒤 휴지·고밀도 연속 허용 시간), 통합 9개(최대 초당 노트 수·전체/같은 레인 최소 간격·롱노트 중 노트 한도·촘촘/느슨 연속 개수·분당 연타 수·연타 최소 간격·최대 길이). 범위를 벗어나면 한국어 오류.
- 바꾼 값은 모드·난이도별로 이 기기에 저장되고, [규칙 기본값으로 되돌리기]로 지운다(그 난이도의 4키 칸 값도 함께).
- 통합 모드의 노트 양 슬라이더는 목표 초당 노트 수를 비워 둘 때만 규칙 기본 밀도에 (슬라이더 ÷ 55)배로 곱한다. 좌·우 버튼 패턴은 기존 방식 2키 전용(잠길 때 이유 표시).
